## convert-batch.sh — 重い FFmpeg 変換を順番に流すバッチ

> **作成日**: 2026-06-16
> **対象 OS**: macOS
> **依存**: `ffmpeg`（`brew install ffmpeg`）

### 概要

15GB 級の動画ファイルを、CPU/メモリを食い潰さないよう **1 本ずつ順番に（同時実行せず）** 変換するスクリプト。引数で渡した各入力ファイルにつき、デフォルトでは以下 2 本を生成する（フラグで片方のみに絞ることも可能。「[解像度を指定する](#解像度を指定する)」参照）。

| 出力                | 用途           | 解像度 |
| ------------------- | -------------- | ------ |
| `…(1080p_H265).mp4` | 通常保存用     | 1080p  |
| `…(720p_H265).mp4`  | モバイル端末用 | 720p   |

コーデックはいずれも H.265（`libx265`）。音声は AAC 128k。ビットレートは 1080p 3000k / 720p 1200k（「[エンコーダとビットレート](#エンコーダとビットレート)」参照）。出力ファイル名は **入力ファイル名から自動生成** され、後述の出力先ディレクトリに保存される。

### 使い方

```bash
cd <tony-stark-labs のクローン先>
```

#### 単体ファイル

```bash
caffeinate -i ./scripts/convert-batch.sh "/path/to/2026-06-04-NBA.mp4"
```

#### 複数ファイル（引数を並べるだけ。改行 `\` はあってもなくてもよい）

```bash
caffeinate -i ./scripts/convert-batch.sh \
  "/path/to/2026-06-04-NBA.mp4" \
  "/path/to/2026-06-05-LAL.mp4" \
  "/path/to/2026-06-06-BOS.mp4"

# 1 行で書く場合
caffeinate -i ./scripts/convert-batch.sh "/path/A.mp4" "/path/B.mp4" "/path/C.mp4"
```

#### 同一ディレクトリの mp4 を一括（シェルのワイルドカード展開）

```bash
caffeinate -i ./scripts/convert-batch.sh "/path/to/inbox/"*.mp4
```

> `caffeinate -i` は長時間処理中の macOS スリープを防ぐ。数時間かかるため付与を推奨する。

#### オプション

オプションの一覧は `./scripts/convert-batch.sh --help` で表示する。フラグは**ファイル引数の前後どちらに置いてもよい**。

#### 解像度を指定する

デフォルトは 1080p / 720p の 2 本を生成する。片方だけで十分な場合は以下フラグで絞れる。

```bash
# 1080p だけ（通常保存用のみ）
caffeinate -i ./scripts/convert-batch.sh --1080p "/path/A.mp4" "/path/B.mp4"

# 720p だけ（モバイル配布用のみ）
caffeinate -i ./scripts/convert-batch.sh --720p "/path/to/inbox/"*.mp4

# ヘルプ
./scripts/convert-batch.sh --help
```

`--1080p` と `--720p` を同時指定するとエラー終了する（意図しないミス防止）。両方が必要なら明示的に `--both` を使うか、フラグなしのデフォルトに任せる。

#### エンコーダとビットレート

エンコーダは **`libx265` 固定**（フラグでの切り替えはしない）。ビットレートはスクリプト先頭の定数で変更する。

```bash
BITRATE_1080P='3000k'
BITRATE_720P='1200k'
```

##### 変換に 1 本 2 時間かかるのは正常

`libx265` の 1080p ソフトウェアエンコードは実測 **約 53 fps**（= 0.88x realtime）で、完全に CPU バウンドである。60fps・2〜3 時間のスポーツ映像なら 2〜3 時間かかるのが相場となる。

**出力先を外付け HDD から本体 SSD に変えても改善しない。** 実測で差は 3.4%（測定ノイズの範囲）だった。3000k = 約 375 KB/秒 しか書いておらず、HDD の帯域を 1% も使っていないためである。

> **測定条件**: M2 Max (12 コア) / 1920x1080・60fps・H.264 7.8Mbps のソースから 1080p を 60 秒分エンコード。`user` 428 秒 / `real` 68.5 秒（= 6.3 並列）で全コアを使い切っていた。

##### ハードウェアエンコード（`hevc_videotoolbox`）を採用しない理由

一度は `--encoder hw` として実装したが、2026-08-02 の実測で **不採用と決定し撤去した**。

速度は確かに速い（1080p で約 349 fps = **6.6 倍**、720p では 20x realtime）。しかし本スクリプトの目的は「iPad 用に圧縮する」ことであり、そこと構造的に噛み合わない。

|                             | 映像ビットレート | サイズ   | 対ソース |
| --------------------------- | ---------------- | -------- | -------- |
| ソース (H.264 720p60)       | 2,191 kbps       | 2.38 GiB | —        |
| `libx265` @ 1200k           | 1,189 kbps       | 1.36 GiB | **−43%** |
| `hevc_videotoolbox` @ 2500k | 2,753 kbps       | 2.96 GiB | **+24%** |

VideoToolbox は同じ画質を得るのに `libx265` より 30〜50% 多くビットを要する。そのため:

- **サイズを揃えれば画質で負ける**（同じ 1200k では明確に劣化する）
- **画質を揃えればサイズで負ける**（上表のとおりソースより太る）

加えて、指定ビットレートを 10% ほど超過して出力する（2500k 指定 → 2753 kbps 実測）。速度が最優先という明確な理由がない限り、採用する意味がない。

##### ⚠️ 「映像が途中で止まり音声だけ続く」— 原因はソース録画の破損（2026-08-02 調査）

CleverGet で取得した録画に、**映像トラックだけが途中で終わっているファイル**が存在する。

|      | ソース（CleverGet / Amazon）                 |
| ---- | -------------------------------------------- |
| 映像 | 1280x720 / 60fps / **752 秒**（12 分 31 秒） |
| 音声 | **8,794 秒**（2 時間 26 分）                 |

これを変換すると、出力も忠実に「映像 752 秒 / 音声 8,794 秒」となり、再生時に映像が止まって音声だけ流れ続ける。**変換処理は正常であり、エンコーダの問題ではない。**

書庫 504 ファイルを走査したところ、同じ症状のファイルが 7 件見つかった。うち `2026-04-26-Knicks vs. Hawks` は 1080p と 720p の 2 本が**まったく同じ 6,472 秒**で終わっており、独立した 2 回のエンコードが同一地点で止まることはあり得ないため、これもソース起因と判断できる。

**対策**: 変換前に `--dry-run` ではなくソース自体を点検する。下記スクリプトで映像と音声の長さのずれを検出できる。破損していた場合は再ダウンロードするしかない（映像データが存在しないため、変換では復元できない）。

##### 出力側の検証

上記とは別に、本スクリプトは変換後に出力を検証する（「[挙動の仕様](#挙動の仕様)」参照）。

- 出力に映像ストリームがない → **失敗扱いにして破棄**
- 出力の映像長がソースの映像長の 99% 未満 → **失敗扱いにして破棄**
- 映像と音声の長さが 1 秒以上ずれている → **警告**（ソース破損に気付ける）
- 出力がソースより大きい → **警告**（圧縮目的に反するため）

比較対象は「ソースの映像長」なので、**壊れたソースを忠実に変換した結果を誤って破棄することはない**。

##### 書庫の点検スクリプト

映像と音声の長さがずれているファイルを洗い出す（読み取りのみ）。

```bash
D="$CONVERT_OUTDIR"   # 点検したい出力先
for f in "$D"/*.mp4; do
  v=$(ffprobe -v error -select_streams v:0 -show_entries stream=duration -of default=nw=1:nk=1 "$f" 2>/dev/null | head -1)
  a=$(ffprobe -v error -select_streams a:0 -show_entries stream=duration -of default=nw=1:nk=1 "$f" 2>/dev/null | head -1)
  case "$v" in '' | 'N/A' | *[!0-9.]*) continue ;; esac
  case "$a" in '' | 'N/A' | *[!0-9.]*) continue ;; esac
  awk -v v="$v" -v a="$a" 'BEGIN { exit !(a > 0 && v < a * 0.95) }' &&
    awk -v n="$(basename "$f")" -v v="$v" -v a="$a" \
      'BEGIN { printf "  %s  映像 %.0fs / 音声 %.0fs (%.1f%%)\n", n, v, a, v / a * 100 }'
done
```

#### 出力先を指定する

`-o` / `--output` で出力先ディレクトリを指定できる。優先順位は以下の通り。

1. `--output <DIR>` （最優先）
2. 環境変数 `CONVERT_OUTDIR`

どちらも無ければエラー終了する。出力先は手元のディスク構成に依存するので、スクリプトには既定値を持たせない（公開リポジトリに手元のパスを書かず、シーズンが変わっても commit せずに済むようにするため）。

```bash
# 単発で別の場所へ出す
caffeinate -i ./scripts/convert-batch.sh -o ~/Movies/inbox "/path/A.mp4"

# 普段の出力先は環境変数で固定する（~/.zshrc.local など、リポジトリの外に書く）
export CONVERT_OUTDIR='/Volumes/<ディスク名>/<出力先のフォルダ>'
```

指定したディレクトリが存在しない場合はエラー終了する（自動作成はしない）。

#### 実行前に予定を確認する（`--dry-run`）

1 ファイルあたり数時間かかるため、**走らせる前に生成予定を確認できる**。変換は一切行わない。

```bash
./scripts/convert-batch.sh --dry-run "/path/"*.mp4
```

```
===== dry-run（変換は行いません） =====
  エンコーダ : libx265 (1080p 3000k / 720p 1200k)
  出力先     : /Volumes/<ディスク名>/<出力先のフォルダ>
  生成対象   : 1080p + 720p
  入力       : 2 件

[1/2] /path/2026-08-02-Test vs. Sample(1920x1080).mp4
      生成            : 2026-08-02-Test vs. Sample(1080p_H265).mp4
      スキップ（既存）: 2026-08-02-Test vs. Sample(720p_H265).mp4   ※ --force で上書き
[2/2] 警告: '/path/存在しない.mp4' が見つかりません。スキップします。
```

入力ファイルに不在があった場合は終了コード 1 を返す。出力先が見つからない場合（外付けボリュームが外れているなど）は、警告を出して予定の表示を続ける。

#### 既存の出力を焼き直す（`--force`）

デフォルトでは既存の出力ファイルをスキップする。意図的に上書きしたい場合に使う。

```bash
caffeinate -i ./scripts/convert-batch.sh --force --1080p "/path/A.mp4"
```

### 引数のルール（重要）

- **渡すのは「入力ファイル」だけ**。変換後のファイル名は指定しない（自動生成される）。
- **フラグはファイル引数の前後どちらに置いてもよい**。
- `-` で始まる名前のファイルを渡す場合のみ、`--` の後ろに置く。

#### ⚠️ スペース・括弧を含むパスのクォート

ファイル名にスペースや `()` が含まれる場合、**エスケープ方法は次のどちらか一方だけを使う**。両方を併用するとパスが壊れて「見つかりません」になる。

```bash
# ✅ 形 A（手打ち推奨）: ダブルクォートで囲む。バックスラッシュは付けない
caffeinate -i ./scripts/convert-batch.sh "/path/Knicks vs. Spurs(1920x1080).mp4"

# ✅ 形 B（Finder からの D&D）: クォートで囲まない。スペース等は \ で自動エスケープ済み
caffeinate -i ./scripts/convert-batch.sh /path/Knicks\ vs.\ Spurs\(1920x1080\).mp4

# ❌ NG（併用）: ダブルクォート内の \ はただの文字として残り、パスが壊れる
caffeinate -i ./scripts/convert-batch.sh "/path/Knicks\ vs.\ Spurs\(1920x1080\).mp4"
```

> Finder からターミナルへドラッグ&ドロップすると **形 B** が自動入力される。その場合は**自分でクォートを足さない**こと。

### 挙動の仕様

| 挙動                     | 内容                                                                                                                                                                                                                                                                                                                  |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 順次実行                 | `&` を付けないため、1 本の変換が終わるまで次を開始しない（同時実行しない）                                                                                                                                                                                                                                            |
| 出力名                   | 入力の `basename`（ディレクトリ・拡張子を除いた名前）＋ サフィックスで自動生成                                                                                                                                                                                                                                        |
| 解像度サフィックスの除去 | 入力ファイル名の**末尾**の `(WIDTHxHEIGHT)` 形式（例: `(1920x1080)`）は、出力名から自動で取り除かれる。直前の `-` / スペース / `_` も併せて除去する（例: `2026-04-29-YOUR-FILE-(1920x1080).mp4` → `2026-04-29-YOUR-FILE(720p_H265).mp4`）。取り除いた結果が同じ名前になる入力があると、変換を始める前にエラー終了する |
| 既存スキップ             | 出力ファイルが既に存在する場合はスキップしてログ表示する（中断時の再実行で続きから処理できる）。`--force` で上書きできる                                                                                                                                                                                              |
| 不在スキップ             | 入力ファイルが見つからない場合は警告を出してスキップし、最後に件数を集計表示する                                                                                                                                                                                                                                      |
| **一時ファイル方式**     | 変換中は `.<出力名>.part.mp4`（隠しファイル）に書き出し、**成功時のみ**本来の名前へ `mv` する。中断・失敗しても不完全な出力ファイルは残らない                                                                                                                                                                         |
| **出力の検証**           | 変換後に ffprobe で映像ストリームの長さを測り、**ソースの 99% 未満なら失敗扱いにして破棄する**。ffmpeg が終了コード 0 を返しても、映像だけが途中で終わった出力はありうるため信用しない。映像と音声の長さが 1 秒以上ずれる場合も警告する                                                                               |
| **中断時の掃除**         | `Ctrl+C`（SIGINT）や SIGTERM を受けると一時ファイルを削除し、終了コード 130（SIGINT）/ 143（SIGTERM）で停止する。次のファイルへ進まない                                                                                                                                                                               |
| 優先度                   | `nice -n 10` でやや優先度を下げ、変換中の他作業の体感を軽くする                                                                                                                                                                                                                                                       |
| stdin 保護               | `ffmpeg -nostdin` でループ中の標準入力を遮断（プロンプト待ちでの停止を防ぐ）                                                                                                                                                                                                                                          |
| **`hvc1` タグ**          | `-tag:v hvc1` を付与する。これがない（`hev1`）と QuickTime / iOS で再生できないことがある                                                                                                                                                                                                                             |
| スケール幅               | `scale=-2:<高さ>` で幅を偶数に丸める。`-1` だと奇数幅になった際に H.265 エンコードが失敗する                                                                                                                                                                                                                          |
| 完了通知                 | 全処理後に macOS の通知（`osascript`）を表示する                                                                                                                                                                                                                                                                      |
| 完了ファイル一覧         | 全処理後に、実際に生成できた（または既に存在した）出力ファイルの一覧を件数付きでターミナルに表示する。変換失敗した出力は含まれない                                                                                                                                                                                    |
| 終了コード               | 変換に失敗した入力、または不在の入力があれば 1、すべて正常なら 0。最後の集計の「変換に失敗した入力」は、入力ファイルの件数で数える                                                                                                                                                                                    |

> **中断後の再実行**: 一時ファイル方式のため、中断しても**手動削除は不要**。そのまま再実行すれば完了済みのファイルはスキップされ、続きから処理される。

## winzip.py — フォルダを Windows でも文字化けしない ZIP にする

引数に渡した各ディレクトリを、`<ディレクトリ名>.zip` として同じ階層に 1 つずつ作る。macOS の Finder の「圧縮」で作った ZIP を Windows で開くと、日本語のファイル名が化けたり、濁点が分かれたりするのを避けるためのスクリプト。

```bash
python3 scripts/winzip.py "<フォルダ A>" "<フォルダ B>"
```

- ZIP の中は `<ディレクトリ名>/…` から始まる（展開するとフォルダごと出てくる）
- ファイル名を NFC に正規化する（macOS の NFD による濁点の分離を直す）。ASCII 以外の名前には、Python の `zipfile` が UTF-8 のフラグを自動で付ける
- `.DS_Store`・`._*`・`__MACOSX`・`.git` などは入れない。空のフォルダは残す（除外した結果、中身が無くなったフォルダも含む）
- シンボリックリンクは、ファイルもフォルダも入れない（リンク先の中身も入れない）
- 同じ名前の ZIP がすでにあれば、上書きせずにスキップする
- 依存は Python 3 の標準ライブラリだけ
