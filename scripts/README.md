## convert-batch.sh — 重い FFmpeg 変換を順番に流すバッチ

> **作成日**: 2026-06-16
> **対象 OS**: macOS
> **依存**: `ffmpeg`（`brew install ffmpeg`）

### 概要

15GB 級の動画ファイルを、CPU/メモリを食い潰さないよう **1 本ずつ順番に（同時実行せず）** 変換するスクリプト。引数で渡した各入力ファイルにつき、以下 2 本を生成する。

| 出力                | 用途           | 解像度 / コーデック                              |
| ------------------- | -------------- | ------------------------------------------------ |
| `…(1080p_H265).mp4` | 通常保存用     | 1080p / H.265、ビットレート 3000k                |
| `…(720p_H265).mp4`  | モバイル端末用 | 720p / H.265、`-preset fast`、ビットレート 1200k |

音声はいずれも AAC 128k。出力ファイル名は **入力ファイル名から自動生成** され、後述の出力先ディレクトリに保存される。

### 使い方

```bash
cd /Users/yoshi/work/dev/my-projects/tony-stark-labs
```

#### 単体ファイル

```bash
caffeinate -i ./scripts/convert-batch.sh "/path/to/2026-06-04-NBA.mp4"
```

#### 複数ファイル（引数を並べるだけ。改行 `\` はあってもなくてもよい）

```bash
caffeinate -i ./scripts/convert-batch.sh \
  "/path/to/2026-06-04-NBA.mp4" \
  "/path/to/2026-06-05-LAL.mp4" \
  "/path/to/2026-06-06-BOS.mp4"

# 1 行で書く場合
caffeinate -i ./scripts/convert-batch.sh "/path/A.mp4" "/path/B.mp4" "/path/C.mp4"
```

#### 同一ディレクトリの mp4 を一括（シェルのワイルドカード展開）

```bash
caffeinate -i ./scripts/convert-batch.sh "/path/to/inbox/"*.mp4
```

> `caffeinate -i` は長時間処理中の macOS スリープを防ぐ。数時間かかるため付与を推奨する。

### 引数のルール（重要）

- **渡すのは「入力ファイル」だけ**。変換後のファイル名は指定しない（自動生成される）。
- **出力先は引数で渡さない**。スクリプト先頭の `OUTDIR` に固定されている（下記）。

#### ⚠️ スペース・括弧を含むパスのクォート

ファイル名にスペースや `()` が含まれる場合、**エスケープ方法は次のどちらか一方だけを使う**。両方を併用するとパスが壊れて「見つかりません」になる。

```bash
# ✅ 形 A（手打ち推奨）: ダブルクォートで囲む。バックスラッシュは付けない
caffeinate -i ./scripts/convert-batch.sh "/path/Knicks vs. Spurs(1920x1080).mp4"

# ✅ 形 B（Finder からの D&D）: クォートで囲まない。スペース等は \ で自動エスケープ済み
caffeinate -i ./scripts/convert-batch.sh /path/Knicks\ vs.\ Spurs\(1920x1080\).mp4

# ❌ NG（併用）: ダブルクォート内の \ はただの文字として残り、パスが壊れる
caffeinate -i ./scripts/convert-batch.sh "/path/Knicks\ vs.\ Spurs\(1920x1080\).mp4"
```

> Finder からターミナルへドラッグ&ドロップすると **形 B** が自動入力される。その場合は**自分でクォートを足さない**こと。

#### 実行前の存在確認（推奨）

変換は時間がかかるため、空振りを避けるべく実行前にパスを確認しておくとよい。

```bash
ls -la "/path/to/2026-06-04-NBA.mp4"
```

### 出力先ディレクトリ（OUTDIR）

出力先はスクリプト先頭の `OUTDIR` で固定している。**年度が変わったらこの 1 行だけ書き換える**。

```bash
# scripts/convert-batch.sh の先頭付近
OUTDIR='/Volumes/KeepTheFaith18TB/01. Video/01. NBA/2025-2026-Season'
```

### 挙動の仕様

| 挙動         | 内容                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------- |
| 順次実行     | `&` を付けないため、1 本の変換が終わるまで次を開始しない（同時実行しない）                     |
| 出力名       | 入力の `basename`（ディレクトリ・拡張子を除いた名前）＋ サフィックスで自動生成                 |
| 既存スキップ | 出力ファイルが既に存在する場合はスキップしてログ表示する（中断時の再実行で続きから処理できる） |
| 不在スキップ | 入力ファイルが見つからない場合は警告を出してスキップし、最後に件数を集計表示する               |
| 優先度       | `nice -n 10` でやや優先度を下げ、変換中の他作業の体感を軽くする                                |
| stdin 保護   | `ffmpeg -nostdin` でループ中の標準入力を遮断（プロンプト待ちでの停止を防ぐ）                   |
| 完了通知     | 全処理後に macOS の通知（`osascript`）を表示する                                               |

> **中断後の再実行に関する注意**: 既存出力はスキップされるため、変換が途中で落ちて**不完全な出力ファイルが残っている**場合は、その 1 本を手動削除してから再実行する。常に上書きし直したい運用に変えることも可能（要相談）。

### メンテナンス

スクリプトを編集したら ShellCheck で検証する。

```bash
brew install shellcheck   # 初回のみ
shellcheck scripts/convert-batch.sh
```

### トラブルシュート

| 症状                                       | 原因                                                                | 対処                                                           |
| ------------------------------------------ | ------------------------------------------------------------------- | -------------------------------------------------------------- |
| `'...' が見つかりません。スキップします。` | クォートとバックスラッシュの併用でパスが壊れている / パスの実体相違 | 「引数のルール」の形 A or B に統一。`ls -la "パス"` で実在確認 |
| `エラー: 出力先が見つかりません`           | 外付けボリューム未マウント                                          | ボリュームをマウントしてから再実行                             |
| `エラー: ffmpeg が見つかりません`          | ffmpeg 未インストール                                               | `brew install ffmpeg`                                          |
| 処理が固まって進まない                     | （通常は `-nostdin` で回避済み）端末側の入力待ち                    | `Ctrl+C` で中断し、出力ファイルの状態を確認して再実行          |
